# 020 Log Inequality (★3)

問題URL: https://atcoder.jp/contests/typical90/tasks/typical90_t

## 問題の要点
- 整数 a, b, c が与えられ、log₂a < b·log₂c が成り立つか判定する
- 制約：a ≤ 10^18, b ≤ 18, c ≤ 13
- 両辺の 2 を底とする指数をとれば a < c^b と同値 → 整数の大小比較に帰着できる

## 使ったアルゴリズム・考え方
- 対数の不等式を「指数側に戻して」整数で比較する（a < c^b）
- c^b は最大 13^18 ≈ 1.1×10^20 で long long（≈9.2×10^18）を超えうるので、__int128_t で計算して比較した
- 計算量は O(b)

## つまずいた点
- 最初は double で log2(a) と b * log2(c) をそのまま比較して WA
- double の精度は約 15〜16 桁しかなく、a が 10^18 近くだと log2(a) が正確に表せない
- 特に a = c^b（等号で No になるべき）や a = c^b ± 1 のような境界ケースで、誤差により大小が逆転・一致判定を誤る

## 学び・次に活かすこと
- 浮動小数点で「等号ギリギリの大小比較」をするのは危険。整数に直せるなら整数で比較する
- log の比較 → 指数に戻す、√ の比較 → 2乗する、割り算の比較 → 掛け算に直す、など「整数のまま比較する」変形を常に考える
- オーバーフローの回避策は複数ある：
  - __int128_t を使う（今回の方法）
  - long long のまま、掛けている途中で a を超えたら打ち切る／a / c と比較して掛ける前に判定する
- 掛け算の最大値を見積もる癖をつける（13^18 は long long に収まらない）

## 参考にした解説
- 典型90問 020 公式解説：浮動小数点誤差を避け、整数で a < c^b を判定する方針。long long でもオーバーフローに気をつければ解ける
