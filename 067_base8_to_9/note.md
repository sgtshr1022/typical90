# 067 Base 8 to 9 (★2)

問題URL: https://atcoder.jp/contests/typical90/tasks/typical90_bo

## 問題の要点
- 黒板に 8 進法の整数 N が書かれている
- 次の操作を K 回行う
  - 黒板の数を 9 進法に直し、現れる数字「8」を「5」に書き直す
  - 書き直した後の数は再び 8 進数とみなす
- K 回後の数を 8 進法で出力する
- 制約: `0 <= N < 8^20`, `1 <= K <= 100`

## 使ったアルゴリズム・考え方
- 問題文の通りにシミュレーションするだけ
- 8進数 → 9進数 を直接やるのは面倒なので、間に10進数（long long）を挟む
  1. 8進文字列 S を long long の値 n に変換（`n = n * 8 + digit`）
  2. n を 9 進法の文字列 T に変換（`n % 9` を取り出して逆順に並べる）
  3. T の中の '8' を '5' に置換
  4. S = T として次の操作へ
- 「8→5 に直すと最大の数字が 7 になる」ので、結果は必ず妥当な 8 進数になる

## つまずいた点
- **N = 0 のコーナーケースで WA**
  - `while (n > 0)` で9進変換していたため、n が 0 だと 1 度もループが回らず T が空文字列になる
  - 結果、出力が空行になって不正解
  - 修正: 変換後に `if (T.empty()) T = "0";` を入れる（または S == "0" なら操作をスキップ）
- サンプル 3 つは全部通っていたので気づきにくかった

## 学び・次に活かすこと
- **制約の下限を必ず読む**。`1 <= N` ではなく `0 <= N` だった。0 や空を特別扱いする必要がないか毎回確認する
- 「値 → 文字列」の変換ループは `while (n > 0)` だと 0 が消える、というのは頻出バグパターン
- 基数変換は「一度10進数（整数型）に落としてから作り直す」のが定石。直接変換しようとしない
- オーバーフロー確認: `8^20 ≈ 1.15e18 < 9.2e18` なので long long で安全
  - しかも9進表記を8進として読み直すと値は必ず小さくなるので、2回目以降はさらに余裕がある

## 参考にした解説
- 公式解説（N = 0 のコーナーケースに注意と明記されている）

## 提出コードの骨格
```cpp
int main() {
  string S;  // 8進数
  int K;
  cin >> S >> K;
  while (K--) {
    // 8進文字列 S -> 10進整数 n
    ll n = 0;
    for (char c : S) n = n * 8 + (c - '0');
    // 10進整数 n -> 9進文字列 T（'8' は '5' に置換）
    string T = "";
    while (n > 0) {
      int t = n % 9;
      if (t == 8) t = 5;
      T += (char)(t + '0');
      n /= 9;
    }
    if (T.empty()) T = "0";   // ★ N = 0 対策
    reverse(T.begin(), T.end());
    S = T;
  }
  cout << S << '\n';
  return 0;
}
```
