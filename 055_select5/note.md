# 未確認 - N個から5個選び積の余りを求める問題

問題URL: (教えてください)

## 問題の要点
- N個の整数A_1〜A_N(5≤N≤100)から5個を選ぶ
- 選んだ5個の積をPで割った余りがQになるような選び方が何通りあるかを求める

## 使ったアルゴリズム・考え方
- N≤100という制約の小ささが最大のヒント。C(100,5)=75,287,520通りしかなく、全組み合わせを直接試しても間に合う
- 5重ループを `i < j < k < l < m` という昇順の条件で回せば、同じ5つ組を重複カウントすることもなく、ちょうどC(N,5)回のループで済む
- 積の計算はAiが最大10^9なのでオーバーフローに注意。ACLの`atcoder::modint`(法を動的に設定できる`using mint = modint;`と`mint::set_mod(P)`)を使い、掛け算のたびに自動でPの余りを取るようにして実装

## つまずいた点
- 最初「i,j,k,lを固定してmを求める」方針を考えたが、同じ5つ組を何度も数えてしまう重複が心配になった
- 実際には「N^5(独立に選ぶ)」と「C(N,5)(昇順のみ)」の計算量を混同しており、後者なら約7500万通りで十分高速に間に合うことを見落としていた
- 5重ループを `i<j<k<l<m` と厳密に昇順にするだけで、重複の心配も計算量の心配も同時に解消されると気づき、シンプルな全探索でAC

## 学び・次に活かすこと
- 「N乗ループは無理」と決めつける前に、**重複を許さない昇順の組み合わせ(C(N,r))として計算量を見積もり直す**習慣をつける。独立試行のN^rと、昇順のみのC(N,r)は計算量が大きく異なる
- N≤100のような小さい制約は、「工夫が必要そう」に見えても、実は直接全探索(適切に重複を除いた形で)で解けることが多い、という感覚を持つ
- `atcoder::modint`は`using mint = modint;` + `mint::set_mod(P)`で、実行時に法を自由に設定できる。Pが入力で与えられる問題ではこの動的modintが便利
